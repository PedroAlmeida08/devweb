Transações
As transações são criadas e destruídas após a execução de cada método.

Passos para Criar e Gerenciar Transações:
1. Criar um Entity Manager (FabricaDeEntityManager)
   em = FabricaDeEntityManager.criarEntityManager();
   O Entity Manager contém uma lista dos objetos monitorados.

2. Criar um objeto que cria ou recupera uma transação existente
   tx = em.getTransaction();
   O Entity Manager cria a transação.

3. Iniciar transação
   tx.begin();
   O Entity Manager envia um begin transaction para o SGBD.

4. Salvar o objeto no BD
   em.persist(umProduto);
   O Entity Manager verifica se o objeto é transiente (Id = null), caso contrário, ocorre um erro, pois o objeto já é destacado (Id != null).

   - Em um SGBD que usa sequence (não é o caso do MySQL, mas sim PostGRE e Oracle):
     - Recupera o próximo valor da sequence.
     - Atribui o valor ao Id.
     - O objeto se torna persistente (Id != null).
     - O produto é adicionado à lista de objetos monitorados pelo Entity Manager.
     - O comando INSERT é agendado para execução no momento do commit.

   - Em um SGBD que não usa sequence (MySQL):
     - O comando INSERT é executado.
     - O valor da coluna Id é atribuído ao Id do objeto.
     - O produto é adicionado à lista de objetos monitorados pelo Entity Manager.
     - A transação é cometida.

5. Commita a transação
   tx.commit();

6. Retorna o Id do produto
   return umProduto.getId();

7. Se houver erro, realiza o rollback
   tx.rollback();

8. Destrói o Entity Manager
   em.close();

Problemas com Entity Manager Estático:
- Se o Entity Manager for criado como variável estática e não for destruído, ao persistir o objeto, ele será salvo na lista de objetos monitorados.
- Mesmo que o objeto tenha sido excluído, o Entity Manager tentará realizar comandos de update, resultando em erro.

Observações Importantes
- Não há transação no método inclui, logo não há commit nem rollback (não há catch).
- Em caso de exceção, ela explodirá na tela, sem ter sido feito rollback, diferente do método inclui, que realiza rollback e depois explodirá a exceção na tela.
